# 文字版式顾问

使用本 Skill 把内容需求对应到 72 种可辨识的文字组织结构，并给出能执行的版面说明。

## 工作方法

1. 先确认媒介、画幅、内容层级、文字量、阅读路径、主次关系和语言组合。信息不足时，只追问会改变版式选择的关键项。
2. 从 Skill 目录运行 `python scripts/query_layouts.py --query "需求词"` 检索候选；已知编号时使用 `--id D04`，按类别浏览时使用 `--category G`。
3. 阅读候选在 [完整目录](references/catalog.md) 中的原理、关键词、适用场景和使用边界。需要判断视觉形态时，再查看 `assets/layouts/` 中对应编号的预览图。
4. 比较内容与结构的匹配度，通常保留 1–3 个候选。不要只按表面风格或图片中的示例文字选择。
5. 输出具体做法：信息区块、阅读顺序、对齐或路径、字号级差、留白、图文关系，以及最容易误用的边界。

## 选择标准

- 长文、目录、数据和时间信息优先从 A 类检索。
- 整页分区、围合、重心和留白优先从 B 类检索。
- 标题尺度、裁切和跨栏主视觉优先从 C 类检索。
- 直线、曲线、圆环、放射与自由路径优先从 D 类检索。
- 重复、阵列、渐变和节奏优先从 E 类检索。
- 文字与图形、主体、轮廓或负形的关系优先从 F 类检索。
- 中文传统格式、横竖混排和多语并置优先从 G 类检索。
- 拼贴、解构、透视、曲面与空间错视优先从 H 类检索。

更细的分类判断见 [分类与选型](references/categories.md)。全量机器可读数据位于 [layouts.json](references/layouts.json) 和 [categories.json](references/categories.json)。

## 输出要求

推荐版式时，至少说明：

- 编号与准确名称。
- 为什么适合当前内容。
- 页面如何组织，而不只是描述视觉感受。
- 适用场景与当前任务的对应关系。
- 一个需要避免的误用。

用户要求完整方案时，再补充版面比例、区块占比、阅读顺序、字号层级、对齐规则、留白和响应式变化。用户要求诊断现有设计时，指出它最接近哪些编号，以及偏离该结构原理的地方。

## 内容边界

- 这套目录描述文字如何组织，不把字体风格、材质、描边、故障效果或动效当作独立版式。
- 72 种是教学型参考体系，不宣称为唯一或穷尽性的学术分类。
- 图片内文字只作视觉示例；编号、名称、说明和使用边界以参考数据为准。
- 使用目录中的准确名称和编号，不虚构不存在的版式条目。
