# 内容与数据规范

## 数据真源

- 网站数据：`data/layouts.json`、`data/categories.json`。
- 图片：`public/images/layouts/`。
- 公开仓库以 `data/` 为内容单一真源；内部生成档案不参与运行时构建，也不进入公开仓库。

不要让前端在浏览器中读取 Markdown 或 YAML；来源格式服务于制作追踪，JSON 服务于产品运行。

## 版式字段

```ts
type LayoutItem = {
  id: string;                    // A01，永久稳定
  categoryId: string;            // A-H
  nameZh: string;
  nameEn: string;
  description: string;           // 一句话结构原理
  keywords: string[];            // 固定 3 个
  suitableFor: string[];         // 首版 2 个
  avoidFor: string[];            // 首版 2 个
  image: {
    src: string;
    width: number;
    height: number;
    ratio: "3:4";
    format: "png";
    opaque: boolean;
    alt: string;
  };
  relatedIds: string[];          // 同类前后相邻 2-3 个
  status: "ready";
};
```

## 分类字段

```ts
type Category = {
  id: string;
  name: string;
  count: number;
  description: string;
};
```

## 文案规则

- 中文名使用 4–8 字的结构性名称，不用风格营销词。
- 英文名主要帮助检索，不作为学术标准术语承诺。
- 结构说明只讲“文字如何被组织”，不讲配色、字体或纸张风格。
- `suitableFor` 写具体内容/媒介任务，如“目录页与章节导航”，不写“高级、好看”。
- `avoidFor` 写约束，如“大段连续正文”“需要精确逐行比较的数据”，不做价值判断。
- 三个关键词分别优先覆盖结构、阅读感受和视觉结果。
- 网站展示信息以 JSON 中的 HTML 文本为准；图片内文字出现误差时不得反向覆盖数据。

## 图片规则

- 正式源图均为 `1086 × 1448`、3:4、PNG、RGB、不透明。
- 文件名保留 `ID-中文名`；返工通过图保留 `-v2`，避免破坏来源追踪。
- 前端必须通过数据路径引用，不在组件内硬编码文件名。
- 衍生 WebP/AVIF 放入单独子目录，不能覆盖 PNG 源图。
- 图片替代文本格式：`{ID} {中文名}版式示例`。

## 关联规则

首版 `relatedIds` 使用同一分类内的相邻项目，保证稳定和可解释。后续若人工建立“相似/对照”关系，应满足：

- 每条 2–4 个关联。
- 至少一个同类相近项；可有一个跨类对照项。
- 关联必须双向，避免 A 推荐 B 而 B 不推荐 A。

## 数据校验

每次修改后至少检查：

- 总数 72，ID 唯一。
- 分类数量为 10/10/8/10/8/8/8/10。
- 图片路径存在，宽高为 1086×1448。
- `keywords` 恰好 3 个。
- `suitableFor`、`avoidFor` 均不为空。
- `relatedIds` 不包含自身且目标存在。
